where do you start?

Three doors. Same room.

Designers don't all think the same way. Some see the card before they know what it does. Some have the whole system and no art. Some have a game in their head and no cards yet. Pick the door that matches your brain — Playproof connects the rest.

You can see the card → start with the look

You already picture it — the title up top, art in the middle, a cost badge in the corner. You just haven't decided what every part means yet. So design first.

1. Open the Layout Designer on a blank canvas.
2. Drop the pieces you can see — title, art frame, cost badge, rules box.
3. Get the look right. Ignore what the numbers mean for now.
4. Define the fields those slots imply (name, cost, rules…).
5. Bind each slot to its field, preview a real card, adjust.

You've got a system → start with the data

The mechanics are solved in your head — costs, stats, types, the math that makes it tick. You know exactly what each card has to track. So define that first; make it pretty after.

1. Open Card Data and define fields by type — cost (number), type (category), rules (text), art (image).
2. Enter a few cards, or paste the CSV you've been balancing in a spreadsheet.
3. Design a layout — or reuse one you already built.
4. Bind the slots to your fields, preview, and tune the numbers live.

[ data-first flow ]

You've got a game, not cards yet → start with the concept

You're still thinking in rules and feel — what the game is before what's printed on a card. Start where the game lives, and let the cards show up when they're ready.

1. Create a game. Write the overview and rules while they're hot.
2. List your components — including "a deck of cards."
3. When it's card time, define the data and a layout, then build the deck as a component.
4. Snapshot it, print the playtest packet, get it to the table.
